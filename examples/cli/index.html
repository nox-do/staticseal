04 / CLI im Reporting-Ablauf

Der letzte Schritt im Reporting-Job.

Zwei Abläufe: eigenständiges HTML verschlüsseln oder separate Ressourcen zuerst bündeln. Die Berichte öffnen in einem neuen Tab; diese Anleitung bleibt geöffnet.

Zwei CLI-Beispiele - eines auswählen

Eigenständigen Bericht verschlüsseln.

Jupyter kann eigenständige HTML-Dateien mit eingebetteten Bildern erstellen. Das folgende Beispiel zeigt die allgemeine CLI-Nutzung, hier mit Passwortschutz. Das Passwort lautet seal.

1. Notebook exportieren - in examples/jupyter/, mit installierten Python-Abhängigkeiten: 

python -m nbconvert --execute --to html --no-input --embed-images \
  --template-file offline.html.j2 bericht.ipynb --output bericht.html

2. Im Repository-Root verschlüsseln:

printf '%s\n' 'seal' | node bin/self-encrypt.mjs \
  --in examples/jupyter/bericht.html \
  --out examples/jupyter/sealed.html --html-page --stdin-password
Jupyter-Bericht öffnen ↗Quellen als ZIP

Ressourcen bündeln und verschlüsseln.

Jinja2 erzeugt HTML, Matplotlib eine separate PNG; das Layout liegt in einer CSS-Datei. Mit --bundle bettet die CLI beide Ressourcen ein. Zur Weitergabe reicht die versiegelte HTML-Datei.

Mit installierten Python-Abhängigkeiten aus dem Repository-Root: 

python examples/python-report/generate.py
node bin/self-encrypt.mjs --in examples/python-report/bericht.html \
  --out examples/python-report/sealed.html --bundle
Python-Bericht öffnen ↗Workflow & Quellen als ZIP
Passphrase & Automation: Die Befehle laufen aus dem Repository-Root mit installierten npm-Abhängigkeiten. --stdin-password liest die Passphrase von der Standardeingabe; ohne diese Option fragt die CLI interaktiv danach. Der Jupyter-Bericht ist mit seal geschützt; der Python-Bericht wurde mit --no-password erstellt.
